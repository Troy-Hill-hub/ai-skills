# 浏览器下载与故障恢复

## 选择正常浏览器

有目的明确且能力足够的连接器/API 时优先使用；网页访问需要会话时，优先用户已在使用的普通浏览器。先发现本轮可用工具与当前浏览器，再按其文档连接。扩展“安装成功”和当前聊天“已经连接”是两个状态。不要复制会话中的 tab ID、browser ID 或过往工具绑定到新环境。

本次 headless Chrome、普通 urllib 与内置浏览器多次停在验证或超时，而普通 Chrome 能看 SI。不能因为自动化接口 `Page.navigate` 超时就宣布 Chrome 已关闭或官网不可访问。检查实际标签页/用户反馈及落盘文件；不同 API 的列表可能只显示 agent 拥有的标签页。

机构登录只由用户选择其确有资格的机构，并按宿主正常登录流程完成。已有授权和已登录状态继续使用，不反复要求重新登录。只有缺少关键条件且工具无法取得时再问用户。不复制 Cookie、不读取账号口令、不提取浏览器历史、不用整个配置文件做临时 headless profile；不为下载而停用安全保护。

## PDF 预览器与文件下载

本次 SI 已在 Chrome PDF 预览器中正常打开，但扩展返回 Debugger unattached 或控制超时。正确判断是“预览器控制接口受限”，而不是“文件未打开”。

优先尝试当前工具真正支持的下载动作，或官网附件链接。若预览器确实阻挡自动落盘，可提出把 Chrome 的 PDF 偏好改为“下载 PDF 文件”，记录用户是否同意、原偏好和恢复约定。入口是 `chrome://settings/content/pdfDocuments`；这是浏览器打开方式，不等于关闭 Safe Browsing。用户已同意并改好时不再确认。不要偷偷改 profile JSON、凭空声称已改，或在无关任务修改全局偏好。

官方说明可核对：[Chrome PDF 阅读器](https://support.google.com/chrome/answer/16215622?hl=zh-Hans)、[下载文件](https://support.google.com/chrome/answer/95759?hl=zh-Hans)。界面名称和可用接口以当前版本为准。

## Windows 备用启动器

`launch-browser.ps1` 通过 `Shell.Application.ShellExecute` 调用已安装的普通 Chrome 或 Edge，在现有正常会话中打开经过核实的 HTTPS 附件地址。它不是浏览器自动化 SDK；当宿主禁止此方式或要求特定浏览器接口时，应遵守宿主要求，用允许的接口执行等效导航。

- 一个小批次用一次浏览器调用传多个已编码、双引号包围的 URL，不逐个冷启动许多进程。
- 默认最多 2 个新请求，可明确 `-Max 1..8`。大文件用 1–2 个，不要照搬本次一度使用的 8 个批量。
- `-DryRun` 只打印请求，不打开页面、不写启动日志；用于检查主机、编号和浏览器路径。
- 默认跳过下载目录里已存在的正式文件（包括 `(1)` 副本）以及已经请求过的 URL。已存在不等于核验通过，应运行 ingest。
- 重试要显式指定 `-Ids ... -Retry`；不要因 30 秒没有最终文件就不断重发。`-Force` 仅允许已有正式文件时再次请求，既不删除文件也不解除任何浏览器拦截。
- 日志只说明请求发出，不证明下载成功。每个 job 最终以 ingest 的完整性/身份核验及输出为准。
- Edge 是用户同意后的备用浏览器，不保证继承 Chrome 的登录状态；需要时重新核对合法访问。不要把用户此前同意一次 Edge 备用上升为所有任务强制使用 Edge。

## 等待与停滞

只检查用户指定的下载目录和当前已知任务。`.crdownload` / `.part`、零字节文件或改名未完成者不归档。临时文件大小、修改时间的变化可以说明有传输活动；文件长度不一定等于实际收到的连续字节数，也不能据此保证 ETA。

| 现象 | 处理 |
| --- | --- |
| 找到官网链接但 HTTP 403/HTML | 记录访问未核实，使用已授权正常浏览器；不循环重试同一脚本 |
| PDF 可见而接口失联 | 检查预览器限制与下载文件，不先归咎于登录 |
| 临时文件持续增长 | 继续等待，做其他尚需完成的核验；不要重复请求大文件 |
| 正式文件带 `(1)` 后缀 | ingest 已支持；不漏算、不清理用户副本 |
| 文件名与 DOI 编号不同 | 回官网核对实际 href，不能改写成推测编号 |
| 文件长期无变化 | 查看浏览器状态或可用下载状态；排除网络/排队/验证，针对该 job 有理由地重试一次或使用获准的备用浏览器 |
| 下载页出现验证码/安全警告 | 遵守宿主确认/接管规则；不自行绕过、不关闭保护 |
| 工具明确下达 stop / 安全停止 | 立即停止该轮相关工作，如实说明原因；不换接口规避停用要求 |
| 用户说“不管这几篇了” | 停止监视和新请求，mark 为 skipped_user_request，保留已核验文件和清单 |

同一路线连续失败且无新证据时换路线或报告具体缺口，不按固定次数轰炸官网。一次 403 不等于以后永远不再尝试；用户完成登录、浏览器偏好已改变、官网 href 已纠正等属于新的证据。机构/安全验证没解决时不要假装已经下载完成。

本包不控制浏览器下载管理器；CLI 停止不代表已发出的浏览器传输被取消。需要取消时用宿主允许的界面，只取消本任务的下载，不关闭用户全部 Chrome/Edge 或删除下载目录。
